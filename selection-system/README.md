# 경기지역본부 이력서 선정 — 간편 신청 버전

## 현재 구현
- 기존 `waiting-order-dashboard` 저장소 `data.json`의 대기자 명단과 대기순번을 조회
- **성명 또는 초성**(예: `ㅇㄷㅈ`) 검색 후 신청자 직접 선택; 성명만 같으면 **지부·대기순번**을 나란히 표시
- 생년월일 인증/지부 선택 입력란 제거; **성명 선택만으로는 본인인증이 불가능**하여 대리 신청 위험이 있음
- 소형 공고는 `selection-notices/<id>.json`에 **`"type": "small"`**, 대형 공고는 `"type": "large"` 지정
- 소형 희망 X/공란이면 소형 신청 불가. **활동 미희망자는 소형 지원 대상이 아님**
- 기존 비고의 **명확한** `소형근무중`, `소형근무완료`, `소형 이력서 선정` 등의 표현만 소형 자격 제한에 활용
- 기존 비고에 소형근무 중이라고 명시된 경우 대형 신청도 차단
- 이번 시스템의 동일 대기기간 중 소형 지원 이력은 기록된 접수 시트 G/H열(모집유형·대기회차 종료일)로 중복 검사
- **비고로 상태를 판단하기 어려운 경우에는 자동 차단을 보장하지 않음.** 별도 이력관리 시트는 만들지 않음
- 접수 링크에서 **전체 대기순번 확인**을 눌러 `&view=ranking` 화면으로 이동
- 공고 JSON에 공개해도 되는 담당자 정보가 있으면 표시:
  `"contact": {"name":"...","branch":"...","role":"...","phone":"..."}`.
  개인정보 연락처를 임의로 가져오지 않으며 **공개 승인된 업무용 번호만** 사용
- 접수 결과는 기존 Google Sheet `경기지역본부 이력서 선정 희망자 접수` 저장
- 기존 대기자 `data.json`과 비공개 참석자명부는 수정하지 않음

## 반드시 할 일 — 기존 Apps Script 웹 앱 버전 갱신
1. GitHub의 `selection-system/Code.gs` 전체 내용을 Google Apps Script 기존 `Code.gs` 파일에 덮어쓰기.
2. GitHub의 `selection-system/Index.html` 전체 내용을 기존 `Index.html` 파일에 덮어쓰기.
3. 저장한 후 상단 **배포 → 배포 관리 → 현재 웹 앱 편집(연필) → 버전: 새 버전 → 배포**.
4. 기존 `/exec` 웹 앱 URL을 열어서 이름/초성 검색, 지부·순번 선택, 전체 순번 링크 표시 확인.
5. Google Sheet에 이미 있는 `희망접수` 시트는 그대로 유지. **새로운 setup 실행이나 시트 추가는 필요 없음**.
6. 기존 `AUTH_SHEET_ID` 스크립트 속성은 코드에서 더 이상 사용하지 않으므로 수정할 필요 없음. 필요하면 관리자 판단으로 나중에 삭제.

## 새 공고 예
```json

  "id": "2026-11-xx-example",
  "status": "open",
  "type": "small",
  "deadline": "2026-11-xxT15:00:00+09:00",
  "project": "현장명",
  "site": "현장주소",
  "rental": "임대사",
  "wage": "임단협",
  "notes": [],
  "signupUrl": "실제-Apps-Script-배포-URL?id=2026-11-xx-example"
}
```

## 제한
- 비고를 정형 데이터로 관리하지 않는 한, **소형근무 중/완료/과거 소형선정 여부를 100% 자동 판정할 수 없음**. 명확히 기록된 경우만 차단하며 그 외에는 관리자 검토 필요.
- 실제 최종 선순위 선정 전 기존 인센티브와 자격·경력 조건은 관리자가 확인.
- 신청자 이름과 지부/순번은 링크를 아는 사람이 볼 수 있음. 성명만으로 타인이 선택할 위험도 있음.
- GitHub 소스 코드를 수정해도 배포된 Google Apps Script에 **자동 반영되지 않음**. 두 파일 업데이트와 새 버전 배포가 필요.
- 공개 승인 없는 간부 개인 전화번호를 공고에 넣지 않음.
