# 경기지역본부 이력서 선정 접수 — 운영 규칙

## 핵심
- **이력서 희망 신청은 여러 공고에 여러 번 할 수 있다.** 한 공고에 유효한 접수는 1건만 가능하며 취소·반려된 건은 실시간 선순위에서 제외된다.
- **소형근무 실제 수행은 동일 대기기간에 1회만 가능**하다. 이력서 신청·선정 사실만으로 근무 완료 처리하지 않는다. 한 조합원이 여러 공고에 동시에 희망 신청할 수 있으나, 하나의 이력서 선정이 확정되면 선정 취소 전까지 다른 공고 신청·선정을 막는다.
- 소형 공고는 대기명단 `isSub: "O"`(소형 활동 희망)인 조합원만 신청 가능하다. X/공란은 신청 불가.
- 현재 소형근무 **중**으로 명확하게 적힌 사람은 대형·소형 모두 신청 제한. 소형근무 **완료**로 명확하게 적힌 사람은 소형 신청 제한.
- 소형근무 중/완료 여부는 기존 `data.json` 비고의 명확한 표현을 참고한다. **비고가 부정확하거나 과거 대기기간의 이력인지 불분명하면 자동으로 정확히 구분할 수 없다.** 별도 근무이력 관리 시스템은 추가하지 않는다.
- 조합원 취소는 **성명 + 생년월일 6자리(YYMMDD)**로 비공개 `참석자명부_인증용_비공개` 시트에서 서버 대조한다. 일반 신청은 접수 마감 전, 이력서 선정된 사람은 선정 후에도 취소할 수 있다. 취소코드는 사용하지 않는다. 관리자 반려는 별도 관리자 화면과 `ADMIN_REVIEW_PASSWORD` 스크립트 속성으로 인증한다.
- 성명/초성 한 글자부터 자동검색; 동명이인은 지부·대기순번으로 구별. 성명 선택만으로는 본인인증이 되지 않는다.
- 신청 화면에는 상단 **본인·전체 대기순번 현황판 링크**, 하단 **해당 공고의 실시간 희망자 선순위 상위 3명만** 표시한다. 관리자는 전원을 확인한다.
- 공고 담당자 정보는 `contact`에 직접 입력하거나 기존 공개 간부 연락처 데이터의 남부지부장/본부 사무장 직책을 조회할 수 있다. 전화번호가 있으면 터치 통화 링크를 제공한다.
- 기존 구글 시트 `희망접수`를 계속 사용하며 기존 접수 내역은 보존한다.

## 앱스크립트 배포
1. 기존 선정 시스템 Apps Script 프로젝트의 `Code.gs`, `Index.html`에 GitHub의 동일 경로 전체 코드를 각각 붙여넣는다.
2. 프로젝트 설정 → 스크립트 속성에 `ADMIN_REVIEW_PASSWORD`를 12자 이상(권장 16자 이상)으로 설정한다. **`AUTH_SHEET_ID`는 기존 비공개 `참석자명부_인증용_비공개` Google Sheet의 ID**로 설정한다. `인증명단` 탭 A~C열은 `성명` / `소속지부` / `생년월일`이다. 비밀번호·비공개 시트 ID·생년월일은 GitHub에 기재하지 않는다.
3. 저장 → **배포 → 배포 관리 → 현재 웹 앱 편집 → 새 버전 → 배포**.
4. 기존 접수 시트를 쓰고 있다면 `setup()`을 다시 실행하지 않는다.
5. 일반 신청 링크: `.../exec?id=<공고ID>`, 관리자 링크: `.../exec?id=<공고ID>&view=admin`.
6. 공고의 `type`은 `small` 또는 `large`. `deadline`이 지난 공고는 자동 마감.
7. 신청·취소·반려·실시간 선순위 동작을 테스트한 후 현장에 배포한다.

## 주의
- GitHub 소스가 수정돼도 이미 배포된 Apps Script에 자동 반영되지 않는다.
- 소형 **근무** 완료/진행의 정확한 판정은 기존 명단 비고의 기록 품질에 달려 있다.
- 공개 웹앱에서는 이름 선택만으로 타인 명의 신청을 완전히 방지할 수 없다. 생년월일도 강한 본인인증 수단은 아니므로 비공개 시트 권한을 유지하고 생년월일 인증 실패는 30분 동안 5회 이후 제한한다.
